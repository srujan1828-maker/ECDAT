## 1. Key Accomplishments & Deliverables

### 1.1 Pure-Python Format Identification (`binary_identifier.py`)
- Traverses and parses binary signatures without relying on `file` or `libmagic`:
  - **Executables**: ELF (32/64-bit, Little/Big-Endian, x86, x64, ARM, AArch64, MIPS, RISC-V), PE/COFF (32/64-bit), Mach-O (32/64-bit, Universal FAT).
  - **Firmware Containers**: U-Boot uImage (magic `0x27051956`), FIT / Device Tree Blob (`0xd00dfeed`), SquashFS (`hsqs`, `sqsh`), CPIO (`070701`, `070702`, `070707`).
  - **Compressed Archives**: ZIP, POSIX Tar, Gzip.
  - **Raw Blobs**: Shannon entropy mapping and fallback triage.

### 1.2 Structural Metadata & Section Tables (`binary_metadata.py`)
- Extracts section headers (`.text`, `.rodata`, `.data`, `.rdata`, `.symtab`, `.dynamic`), virtual addresses, file offsets, and access permissions.
- Distinguishes stripped from unstripped binaries based on symbol table presence.
- Recovers GNU Build IDs from `.note.gnu.build-id` sections.
- Resolves raw byte offsets to enclosing sections.

### 1.3 Symbol Table Intelligence & Defined/Undefined Distinctions (`binary_symbols.py`)
- Implements the critical research distinction:
  - **Defined Function (`is_defined: True`)**: Implemented within the binary text segment $\rightarrow$ **$E3$ Evidence**.
  - **Undefined Imported Symbol (`is_defined: False`)**: External dynamic API dependency $\rightarrow$ **$E2$ Evidence**.
- Knowledge base classification recognizes PQC (Kyber/ML-KEM, Dilithium/ML-DSA, SPHINCS+, Falcon), Classical Asymmetric (RSA, ECDSA, ECDH, X25519), Symmetric (AES, ChaCha20, SM4, DES, 3DES), and Hash primitives (SHA-256, SHA-3, MD5, SHA-1).

### 1.4 Dynamic Shared Library & Import Analysis (`binary_imports.py`)
- Recovers dynamic library dependencies:
  - ELF `DT_NEEDED` records via `.dynamic` and `.dynstr`.
  - PE Import Directory DLLs (`bcrypt.dll`, `crypt32.dll`, `ncrypt.dll`, `libcrypto-3.dll`).
  - Mach-O `LC_LOAD_DYLIB` entries.
- Maps linkages to cryptographic suites without conflating library linkage with runtime execution.

### 1.5 String Extraction & Secret Candidate Masking (`binary_strings.py`)
- Recovers ASCII and UTF-16LE string literals matching cryptographic primitives and OIDs.
- **Strict Confidentiality**: Embedded PEM RSA/EC/OpenSSH private keys and certificates are parsed and validated, but raw key material is strictly masked as `SECRET_INDICATOR_DETECTED`. No raw keys are ever emitted in scan results.

### 1.6 Cryptographic Constants & Byte Signatures Knowledge Base (`binary_signatures.py` & YAML)
- Authored `backend/knowledge/binary_crypto_signatures.yaml` containing:
  - AES forward and inverse S-boxes
  - DES initial permutation table
  - ChaCha20 constants (`"expand 32-byte k"`)
  - Hash IVs (MD5, SHA-1, SHA-256, SHA-384, SHA-512, Keccak round constants)
  - Word reversal checking for cross-endian compilation detection
  - PQC NTT polynomial constants (ML-KEM/Kyber twiddle factors, ML-DSA/Dilithium NTT tables)
  - ASN.1 DER OIDs (RSA, ECDSA, Ed25519, ML-KEM-768, ML-DSA-65)

### 1.7 Bounded Multi-Format Firmware Extraction (`firmware_extractor.py`)
- Pure-Python recursive unpacker enforcing hard resource ceilings:
  - Max recursion depth: 3
  - Max entries unpacked: 200
  - Max decompressed size: 16 MiB cumulative, 8 MiB per entry
  - Path traversal defense: rejects `..`, leading slashes, null bytes
  - Cycle detection: in-memory hash set of unpacked blobs
  - Rejection of encrypted ZIP entries

### 1.8 Pluggable Deep Reverse Engineering Architecture (`deep_re_plugins.py`)
- Standardized `DiscoveryEngine` plugin interface (`GhidraEngine`, `AngrEngine`, `YaraEngine`).
- **Observability**: When tools are not installed in the execution environment, the plugins report `status: "SCANNER_UNAVAILABLE"` with diagnostic messages, ensuring the platform never crashes or falsely claims the binary is free of cryptographic components.

### 1.9 Evidence & Relational Asset Graph Integration (`binary_pipeline.py`)
- Maps observations directly to P0 `Evidence` objects with immutable provenance records.
- Populates `AssetGraphService`:
  - Containers: `AssetType.FIRMWARE` linked via `RelationshipType.CONTAINS` to member `AssetType.BINARY` nodes.
  - Linked Libraries: `AssetType.CRYPTO_LIBRARY` linked via `RelationshipType.USES`.
  - Algorithms: `AssetType.ALGORITHM` linked via `RelationshipType.IMPLEMENTS` (for defined functions/signatures) or `RelationshipType.CALLS` (for imported symbols).

## 3. Compliance with Research Axioms

1. $\text{STRING} \neq \text{USE}$: String literals in read-only data are classified strictly as **$E1$ Pattern Candidates**.
2. $\text{IMPORT} \neq \text{USE}$: External shared libraries (`DT_NEEDED`, DLLs) and undefined dynamic symbols are classified as **$E2$ Structured Assets** with explicit limitations that runtime execution depends on control flow.
3. $\text{SYMBOL} \neq \text{USE}$: Defined functions compiled into the text segment receive **$E3$ Actual Reference** evidence, with explicit notice that dynamic reachability requires control-flow analysis.
4. $\text{DISASSEMBLY} \neq \text{EXECUTION}$: Deep decompilers (Ghidra/angr) report availability health, and static pattern matching never claims runtime execution.
5. **No Data / Secret Leaks**: Embedded private keys are masked with `SECRET_INDICATOR_DETECTED`.
