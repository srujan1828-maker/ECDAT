# ECDAT V4 — P2.2 Agility Explainability & Provenance
## Reason Chains, Rule Linkage, and Audit Traceability

### 1. Explainability Architecture

To eliminate black-box judgments, every agility assessment produced by ECDAT V4 provides an explainable reason chain:
- Each dimension links to specific firing rules from `crypto_agility_rules.yaml`.
- Each reason references the exact underlying evidence IDs ($E0$–$E5$) that triggered the condition.
- The system surfaces concrete positive factors (enablers) and negative factors (barriers).

---

### 2. Machine-Readable Reason Model

```python
@dataclass
class AgilityReason:
    rule_id: str                   # e.g., "AGL-ALG-001"
    dimension: AgilityDimension    # e.g., AgilityDimension.ALGORITHM
    impact: str                    # "POSITIVE", "NEGATIVE", "NEUTRAL"
    summary: str                   # Human-readable explanation
    evidence_ids: List[str]        # Concrete pointers to evidence items
    details: Dict[str, Any]        # Context attributes and parameters
```

### 4. Cryptographic Provenance & Tamper Evidence

Every assessment includes cryptographic SHA-256 hashes recording the state of the analysis:
1. **`evidence_hash`**: SHA-256 over normalized, canonicalized evidence IDs and descriptions.
2. **`configuration_hash`**: SHA-256 over active rule definitions and thresholds.
3. **`kb_version`**: Frozen knowledge base tag (`2024.1`).
4. **`engine_version`**: Active implementation version (`4.2.0-agility`).

Any modification to inputs or rules produces a differing hash, guaranteeing verifiable auditability.
