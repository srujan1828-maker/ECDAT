# ECDAT V4 — P2.1 Risk Model & Rule Engine
## Formal Specification of Deterministic Risk Evaluation

### 1. Risk Evaluation Philosophy
Risk in ECDAT V4 is not an opaque numerical score. It is a dual-coordinate determination:
$$\text{Risk} = (\text{Severity}, \text{Confidence})$$

- **Severity** reflects the cryptographic and business consequence if the weakness is exploited.
- **Confidence** reflects the empirical quality and convergence of evidence establishing that the weakness exists on the asset.

A critical vulnerability inferred from a static dependency import has $(\text{Severity}=\text{CRITICAL}, \text{Confidence}=\text{INFERRED})$.
A low-risk legacy cipher negotiated during an active TLS handshake has $(\text{Severity}=\text{LOW}, \text{Confidence}=\text{MEASURED})$.

---

### 2. Severity Taxonomy

| Severity | Definition | Examples |
| :--- | :--- | :--- |
| `CRITICAL` | Classical break or active exploitation possible; immediate compliance violation | Single DES, MD5 signature, expired leaf certificate, TLS 1.0 on sensitive endpoint |
| `HIGH` | Deprecated algorithm; quantum-vulnerable KEX on internet-facing long-retention asset (HNDL); key size $< 112$ bits | 3DES, RSA-1024, unverified certificate trust, unmitigated HNDL on sensitive data |
| `MEDIUM` | Quantum-vulnerable classical public-key algorithm (RSA-2048, ECC P-256); symmetric key weakened by Grover ($< 128$ bits) | Standard RSA-2048 / P-256 without PQC; AES-128 under Grover attack |
| `LOW` | Legacy protocol version supported (but not negotiated); minor configuration deficiency | TLS 1.1 offered in server hello but TLS 1.3 negotiated |
| `INFO` | Informational status; PQC hybrid negotiated; non-vulnerable baseline | Pure AES-256, ML-KEM-768 hybrid KEX |
| `UNKNOWN` | Missing required parameters preventing deterministic severity assessment | RSA without key size parameter ($UNK-001$); scanner unavailable ($UNK-002$) |

---

### 3. Confidence Taxonomy

| Confidence Level | Criteria | Typical Evidence Source |
| :--- | :--- | :--- |
| `CORROBORATED` | Multiple independent, concordant observations across different engines | $E3$ Network handshake + $E2$ Static symbol match |
| `MEASURED` | Single direct runtime or dynamic observation ($E3$–$E5$) | $E4$ TLS handshake negotiation or X.509 leaf parsing |
| `INFERRED` | Static code reference, binary string, or package dependency ($E1$–$E2$) | Source AST pattern, ELF import table, `package.json` |
| `UNVERIFIED` | Declarative configuration or unconfirmed metadata | Config file entry not verified against active runtime |
| `CONTRADICTED` | Conflicting observations present across evidence items | Scanner reports TLS 1.3 negotiated but binary lacks TLS 1.3 symbols |
| `UNKNOWN` | No evidence items or $E0$ placeholder | Pure algorithm name lookup without scan evidence |

### 4. Rule Catalog (`backend/knowledge/crypto_risk_rules.yaml`)

| Rule ID | Name | Trigger Condition | Severity | Result Factor |
| :--- | :--- | :--- | :--- | :--- |
| `LEG-001` | Deprecated Algorithm | Algorithm NIST status `DEPRECATED` or `PROHIBITED` | HIGH | `DEPRECATED_ALGORITHM` |
| `LEG-002` | Broken Algorithm | Algorithm status `INSUFFICIENT` or `BROKEN` | CRITICAL | `WEAK_ALGORITHM` |
| `PQ-KEX-001` | Quantum Vulnerable KEX | Shor-vulnerable algorithm in `KEY_ESTABLISHMENT` | HIGH / MEDIUM | `QUANTUM_VULNERABLE_KEX` |
| `PQ-SIG-001` | Quantum Vulnerable Signature | Shor-vulnerable algorithm in `SIGNATURE` | MEDIUM | `QUANTUM_VULNERABLE_SIGNATURE` |
| `PQ-ENC-001` | Quantum Vulnerable Encryption | Shor-vulnerable algorithm in `PUBLIC_KEY_ENCRYPTION` | HIGH | `QUANTUM_VULNERABLE_ENCRYPTION` |
| `PQ-SYM-001` | Grover Weakened Symmetric | Grover-halved bits $< 128$ in `SYMMETRIC_ENCRYPTION` | MEDIUM | `QUANTUM_WEAKENED_SYMMETRIC` |
| `TLS-001` | Legacy TLS Negotiated | Negotiated version $\in \{\text{TLS 1.0}, \text{TLS 1.1}\}$ | HIGH | `LEGACY_PROTOCOL` |
| `TLS-002` | Legacy TLS Supported | Supported version $\in \{\text{TLS 1.0}, \text{TLS 1.1}\}$ | LOW | `LEGACY_PROTOCOL` |
| `CERT-001` | Expired Certificate | Certificate `is_expired == True` | CRITICAL | `EXPIRED_CERTIFICATE` |
| `CERT-002` | Unverified Trust | Certificate `trust_validated == False` | HIGH | `UNVERIFIED_CERTIFICATE_TRUST` |
| `HNDL-001` | HNDL Exposure | Shor-vulnerable KEX + External exposure + High retention | CRITICAL / HIGH | `HNDL_EXPOSURE` |
| `UNK-001` | Unknown Parameters | Algorithm requires parameters (e.g. key size) and `parameter == None` | UNKNOWN | `UNKNOWN_PARAMETERS` |
| `UNK-002` | Scanner Unavailable | Scanner execution failed or target unreachable | UNKNOWN | `SCANNER_UNAVAILABLE` |
