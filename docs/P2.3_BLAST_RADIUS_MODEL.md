# ECDAT V4 P2.3 — Blast Radius Data & Impact Model

## 1. Categorical States (`BlastRadiusState`)
Rather than reducing graph reachability to an opaque integer, P2.3 classifies the topological posture into categorical states:

| State | Definition | Rationale |
| :--- | :--- | :--- |
| `NO_DEPENDENTS_OBSERVED` | Zero dependent assets observed in graph. | Graph successfully traversed; no incoming edges found. |
| `DIRECT_ONLY` | Only 1-hop direct consumers exist. | No multi-hop propagation observed. |
| `TRANSITIVE` | Multi-hop downstream consumers exist. | Intermediate services or components propagate changes. |
| `MULTI_PATH` | 2+ independent paths connect consumer. | Redundant or diamond-DAG dependency links exist. |
| `CONTAINED` | Transitive impact restricted to single module. | Limited architectural footprint despite depth > 1. |
| `WIDESPREAD` | Impact spans $\ge 3$ services or $\ge 15$ assets. | Extensive cross-cutting blast radius. |
| `INCONCLUSIVE` | Contradictory evidence detected. | E.g., conflicting graph links vs dead-code markers. |
| `SCANNER_UNAVAILABLE` | Graph/dependency scanner failed. | Environment error or unmonitored dependency tier. |
| `UNKNOWN` | Insufficient evidence to classify. | Graph topology absent or unlinked. |

---

## 2. Impact Scope Categories (`ImpactCategory`)
Architectural scope of downstream effects:
- `NONE_OBSERVED`: No downstream impact observed.
- `LOCAL`: Confined to single file or internal module.
- `DIRECT`: Direct single-hop consumer affected.
- `TRANSITIVE`: Indirect consumer within same application boundary.
- `MULTI_SERVICE`: Spans $\ge 2$ independent microservices.
- `CROSS_DEPLOYMENT`: Spans $\ge 2$ independent deployment units (Kubernetes/VM clusters).
- `WIDESPREAD`: Spans $\ge 5$ services or $\ge 20$ assets.
- `INCONCLUSIVE` / `SCANNER_UNAVAILABLE` / `UNKNOWN`.

---

## 3. Architectural Criticality (`CriticalityLevel`)
Evaluates the architectural importance of the affected blast radius based strictly on evidenced metadata:
- `CRITICAL`: Asset or downstream consumer is verified in production (`is_production == True`).
- `HIGH`: Asset directly protects persistent/sensitive data assets (`DATA_ASSET`) or is an externally exposed ingress endpoint (`is_externally_exposed == True`).
- `MEDIUM`: Asset serves internal microservices or applications.
- `LOW`: Asset resides in development/ephemeral test environments (`environment == 'dev'`).
- `UNKNOWN`: Insufficient metadata to evaluate without speculation.

> **Axiom**: High dependent count reflects architectural footprint, not business importance. A dev harness with 50 mock consumers remains `LOW` criticality.

---

## 4. `DependencyPath` Dataclass
Every connection from an upstream consumer to the target is preserved with its full provenance:
```python
@dataclass
class DependencyPath:
    path_id: str                          # Deterministic 16-char SHA-256
    source_asset: str                     # Caller ID
    target_asset: str                     # Target asset ID
    node_sequence: List[str]              # ['web-gateway', 'auth-api', 'target']
    relationship_sequence: List[str]      # ['CALLS', 'USES']
    path_length: int                      # Number of hops (e.g. 2)
    direct_or_transitive: str             # "DIRECT" or "TRANSITIVE"
    evidence_refs: List[str]              # Provenance evidence IDs
    confidence: str                       # MEASURED | INFERRED | CONTRADICTED
    limitations: List[str]                # Traversal notes
```
