# ECDAT V4 — P1.3 Hardening Report
## Adversarial Network Intelligence Validation

### 1. SSRF and Validation Controls
- **DNS Rebinding Prevention**: Verified that hostname resolution occurs independently in a bounded subprocess, and the exact vetted IPv4/IPv6 address is passed to all subsequent socket connections.
- **RFC1918 & Local IP Blocking**: Validated that `resolve_target` explicitly rejects global and link-local IPs (e.g. `127.0.0.1`, `10.x`, `169.254.x`) unless an explicit test environment bypass (`ECDAT_ALLOWED_CIDRS`) is provided.
- **Protocol Smuggling**: Validated that `clean_target_host` forcibly strips `username:password` blocks in the URL to prevent protocol smuggling via basic auth formatting.

### 2. Timeouts and Limits
- **Connection Bound**: Each individual TCP handshake enforces strict timeouts.
- **Deadline Propagator**: The TLS analyzer consumes a monotonic deadline; if `time.monotonic() > deadline`, capability probing loops cleanly exit without emitting hallucinated evidence.
- **Memory Boundaries**: SSH KEXINIT payload decoding uses robust integer boundary checks (`_parse_namelist`) to prevent out-of-bounds bytearray access on malformed, oversized, or truncated server packets.

### 3. State Semantics Hardening
- **ADVERTISED vs NEGOTIATED**: Validated that X.509 intermediates and SSH KEX algorithms are exclusively modeled as `ADVERTISED`. Only the explicitly negotiated TLS cipher over an established TLS session receives the `NEGOTIATED` label.
- **INCONCLUSIVE mapping**: If a cipher test fails due to network unreliability rather than an explicit TLS rejection, the state is recorded as `INCONCLUSIVE` rather than `NOT_NEGOTIATED`, preventing false "NOT_SUPPORTED" intelligence on flakey connections.

### 4. Graph Validation & Provenance
- Every generated `NetworkObservation` converts to an `Evidence` object preserving the target hash, the exact scanner version, the `ObservationType`, and explicitly lists the strict `network_state` (e.g., `OFFERED`, `FAILED`) in its `raw_details`.
- Verified that failure to parse an SSH banner or establish an X.509 connection maps to `UNMEASURED` or `FAILED` without generating `NO_CRYPTO` assertions.

### 5. False Positive/Negative Audit
- **False Positive Prevention**: HTTP/3 `Alt-Svc` headers are explicitly contained at the `ADVERTISED` boundary. The analyzer explicitly warns that the active scanner is unavailable, meaning no graph edge asserts HTTP/3 was successfully *negotiated*.
- **False Negative Prevention**: If a generic TLS version connection fails, we log it as failed but still attempt the granular cipher enumeration if the timeout permits, avoiding the assumption that a firewall blocking TLS 1.3 means TLS 1.2 is entirely unavailable.

### Conclusion
P1.3 Network Intelligence pipeline has passed adversarial bounds testing and safely maps complex ephemeral network states into the persistent, monotonic V4 Evidence Graph.
