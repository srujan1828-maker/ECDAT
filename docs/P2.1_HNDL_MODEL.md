# ECDAT V4 — P2.1 Harvest-Now-Decrypt-Later (HNDL) Threat Model
## Contextual Evaluation Criteria and Confidentiality Lifecycles

### 1. The HNDL Threat Paradigm
Harvest-Now-Decrypt-Later (HNDL) refers to adversaries intercepting and archiving encrypted network communications today to decrypt them retroactively once a Cryptanalytically Relevant Quantum Computer (CRQC) becomes operational.

Unlike digital signatures—where retroactive forgery after key expiration does not compromise past message integrity if timestamped—**encrypted payloads remain vulnerable throughout their secrecy lifetime**.

---

### 2. Necessary Conditions for HNDL Exposure

For an asset to be classified as `HNDL_RELEVANT`, all four conditions must be met:

1. **Role Vulnerability**: The cryptographic asset performs `KEY_ESTABLISHMENT` or `PUBLIC_KEY_ENCRYPTION`.
2. **Quantum Vulnerability**: The underlying algorithm is broken by Shor's algorithm ($QuantumImpact == SHOR\_BREAKS$).
3. **Network Interceptibility**: The communication channel is externally accessible or traverses untrusted networks (`exposure == "EXTERNAL"` or `network_reachable == True`).
4. **Data Longevity ($X > \tau_{\text{quantum}}$)**: The data sensitivity is high/critical and requires confidentiality beyond the estimated timeline for CRQC emergence ($retention\_years \ge 5$ years).

---

### 3. Contextual State Resolutions (`HNDLState`)

| State | Condition | Consequence |
| :--- | :--- | :--- |
| `HNDL_RELEVANT` | All 4 conditions definitively met | Immediate prioritization for PQC KEX migration (e.g. ML-KEM) |
| `HNDL_POSSIBLE` | Symmetric cipher with $< 256$ bits (Grover attack), or internal network traversing cross-zone links | Secondary priority; upgrade to AES-256 |
| `HNDL_NOT_APPLICABLE` | Primitive role is `SIGNATURE`, `HASH`, or `MAC`; or cipher is already quantum-resistant (`ML-KEM`, `AES-256`) | HNDL is not a threat to this asset |
| `HNDL_UNKNOWN` | Asset has vulnerable role/algorithm, but `data_sensitivity` or `retention_years` is missing | Explicitly flagged with `UnknownFactor(field="data_lifetime")` |

---

### 4. Mathematical Grounding vs Speculative Guesswork
In ECDAT V4:
- The engine **never assumes** default data lifetimes.
- Missing context generates an explicit request for data classification rather than false positives or false negatives.
- When retention is known to be short (e.g., ephemeral session data with $retention\_years < 2$), the asset is marked `HNDL_NOT_APPLICABLE` even if using classical RSA/ECDH key exchange, because intercepted ciphertext will hold zero commercial value when decrypted decades later.
