# ECDAT V4 — P1.3 Implementation Report
## Network, TLS, X.509, SSH, QUIC & Post-Quantum Cryptographic Intelligence

### 1. Architecture
The network intelligence engine has been modularized into `backend/engine/network/`:
- `network_models.py`: Defines `NetworkEndpoint`, `MeasurementType`, and explicit states (`CONFIGURED`, `SUPPORTED`, `ADVERTISED`, `OFFERED`, `NEGOTIATED`).
- `tls_analyzer.py`: Handles generic TLS probing and bounded capability matrices for TLS versions and cipher suites.
- `x509_analyzer.py`: Performs full X.509 certificate chain extraction and parameter preservation.
- `ssh_analyzer.py`: Safely extracts SSH KEXINIT capabilities without authentication.
- `quic_analyzer.py`: Inspects HTTP Alt-Svc headers for HTTP/3 and QUIC advertisement.
- `resolver.py`: Handles SSRF protection and bounded DNS resolution.

### 2. TLS Analysis
- **Supported vs Negotiated**: We offer single ciphers explicitly to test server support (`SUPPORTED`), and observe default connection to test what actually negotiates (`NEGOTIATED`).
- **TLS 1.2/1.3**: Handled securely via Python 3.11's `ssl` module, isolating the cipher suites and versions. 

### 3. X.509 Analysis
- We use Python 3.10+ `get_unverified_chain()` to retrieve the raw DER bytes of the entire certificate chain offered by the server.
- Extract canonical primitives (e.g., RSA-2048, Ed25519) and correctly model intermediate certificates as `ADVERTISED` and the leaf certificate as `OBSERVED`.

### 4. SSH Analysis
- Pure-Python socket implementation reads the initial `SSH-` banner.
- Sends an initial KEXINIT to solicit the server's KEXINIT.
- Extracts Key Exchange (kex), Host Key, Encryption, MAC, and Compression algorithms.
- Records all capabilities as `ADVERTISED` rather than `NEGOTIATED` since no actual key exchange is completed.

### 5. QUIC / HTTP/3
- Implemented **Level 1** QUIC Detection: Checks for HTTP `Alt-Svc` headers (`h3`).
- **Level 2** (Active UDP QUIC TLS 1.3 handshake) is explicitly marked as `SCANNER_UNAVAILABLE` to avoid shipping a partial, unreliable custom QUIC stack.

### 6. PQC Analysis
- Preserves the `pqc_probe` logic using OpenSSL `s_client` to test hybrid key exchanges (e.g., `X25519MLKEM768`).
- SSH PQC combinations (like `sntrup761x25519-sha512@openssh.com`) are automatically detected in the SSH KEX parsing if supported by the target.

### 7. SSRF and Safety
- All targets must pass DNS resolution inside a bounded subprocess to prevent DNS rebinding in the main process.
- Only global IPs or explicitly allowed CIDRs (`ECDAT_ALLOWED_CIDRS`) are permitted.
- Redirects are NOT followed by default for basic network capability tests to prevent malicious loopback redirects.
- No raw session keys, passwords, or cookies are stored.

### 8. Testing & Validation
- Added `test_p1_network_discovery.py` featuring a mock SSH server and QUIC header parsing tests.
- Re-ran the existing regression suite (204 tests) with full backward compatibility in `network_prober.py` legacy data outputs.

### 9. Limitations & Unsupported Features
- **QUIC Active Probing**: Unsupported (Level 2). Marked explicitly as `SCANNER_UNAVAILABLE`.
- **Exhaustive Cipher Enumeration**: We bounded the list to common ciphers rather than performing an exhaustive O(N) cipher test to preserve performance and prevent scanning bans.
- **Revocation Checks**: Currently limited to identifying if an extension is present, active OCSP/CRL fetching is omitted in this baseline to prevent hanging/blocking.
