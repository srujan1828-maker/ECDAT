# ECDAT V4 — P2.1 Legacy Risk Audit & Modernization Report
## Critical Analysis of Mosca's Theorem & Cryptographic Agility Index (CAI)

### 1. Executive Summary
In ECDAT V3 and earlier prototypes, risk modeling relied on two simplistic paradigms:
1. **Mosca's Theorem ($X + Y > Z$)** evaluated as a single deterministic inequality using global or unmeasured default parameters.
2. **Cryptographic Agility Index (CAI)** calculated as an arbitrary weighted scalar score (e.g., 0–100) lacking verifiable ground truth.

This audit evaluates the theoretical limits and practical failures of these legacy models when subjected to research-grade evaluation, and documents the modernization implemented in ECDAT V4 P2.1.

---

### 2. Mosca's Theorem Audit ($X + Y > Z$)

#### Theoretical Formulation
Mosca’s Theorem states that an organization is in quantum risk if:
$$X + Y > Z$$
Where:
- $X$ = Data shelf-life / confidentiality retention requirement (years).
- $Y$ = Migration time to achieve quantum-safe cryptography (years).
- $Z$ = Time until a Cryptanalytically Relevant Quantum Computer (CRQC) emerges (years).

#### Failure Modes Identified in V3:
1. **Collapsed Context Sensitivity**:
   - V3 treated $X$ as an enterprise-wide constant (e.g., $X = 10$). In reality, data retention requirements vary drastically by asset: session keys ($X \approx 0$), transactional payment tokens ($X \approx 5$), medical records ($X \approx 30$), and classified defense secrets ($X \ge 50$).
2. **Assumption of Known Parameters**:
   - If an asset had an unknown data sensitivity or retention lifecycle, V3 defaulted to a fallback number. This generated false alarms for ephemeral data and missed risks for long-term secrets.
3. **Role Conflation (KEX vs Signature)**:
   - Mosca's Theorem is primarily an **HNDL (Harvest Now, Decrypt Later)** concern affecting **key establishment and public key encryption**. Signatures only require quantum resistance at the time of verification ($Y > Z$); old signatures with valid timestamps do not enable retrospective plaintext decryption. V3 applied Mosca uniformly to signatures, hashes, and symmetric ciphers.
4. **False Precision in $Z$**:
   - $Z$ cannot be known deterministically. Treating $Z$ as a fixed calendar date (e.g., 2030) provides misleading mathematical certainty.

#### V4 P2.1 Modernization:
- Decoupled into `HNDLAnalyzer` (`backend/engine/intelligence/hndl_analyzer.py`).
- Requires explicit `retention_years` and `data_sensitivity`. If missing, the engine evaluates to `HNDLState.HNDL_UNKNOWN` with an explicit `UnknownFactor(field="data_lifetime")`, never a defaulted boolean.
- Restricts HNDL applicability strictly to confidentiality-bearing roles: `KEY_ESTABLISHMENT` and `PUBLIC_KEY_ENCRYPTION`. Signatures evaluate to `HNDL_NOT_APPLICABLE`.
- Legacy `/api/risk/mosca` endpoint is preserved for backward compatibility but augmented with validation flags and explicit limitation notices.

### 3. Cryptographic Agility Index (CAI) Audit

#### Theoretical Formulation
Legacy agility scores typically combined heuristic weights:
$$\text{CAI} = w_1 \cdot \text{HardcodedKeys} + w_2 \cdot \text{CryptoIsolation} + w_3 \cdot \text{AlgorithmConfigurability}$$

#### Failure Modes Identified in V3:
1. **Arbitrary Weighting**:
   - Weights ($w_1, w_2, w_3$) were subjective heuristics with no empirical calibration.
2. **Score Masking**:
   - A system with a hardcoded, broken cipher (e.g., single DES) could score "68/100 (Moderate Agility)" if its configuration files were well-organized, obscuring an immediate, critical exploit.
3. **Inability to Audit Evidence**:
   - Scores could not be decomposed into reproducible evidence levels ($E0$–$E5$) or traceable rule references.

#### V4 P2.1 Modernization:
- Replaced scalar scoring with an **Evidence-Driven Categorical Risk and Agility Model**:
  - Independent **Severity** (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `INFO`, `UNKNOWN`).
  - Traceable **Confidence** (`MEASURED`, `CORROBORATED`, `INFERRED`, `UNVERIFIED`, `CONTRADICTED`, `UNKNOWN`).
  - Fine-grained **PQC Readiness Dimensions**: `key_establishment`, `signature`, `certificate`, `protocol`, `library`, and `application`.
  - Full backward compatibility retained in `backend/engine/agility_engine.py` with zero regressions on existing test suites.

### 4. Summary Matrix

| Capability | Legacy V3 Approach | ECDAT V4 P2.1 Architecture |
| :--- | :--- | :--- |
| **Risk Metric** | Scalar score (0–100) | Categorical Severity + Evidence-based Confidence |
| **PQC Readiness** | Binary boolean flag | 6-role independent readiness state machine |
| **HNDL Analysis** | Global $X + Y > Z$ scalar | Asset-specific contextual evaluation with `HNDL_UNKNOWN` guards |
| **Hybrid KEX** | Conflated with full PQC | `HYBRID_NEGOTIATED` recognized; signature role kept separate |
| **Scanner Failure** | Treated as clean or missing | Explicit `SCANNER_UNAVAILABLE` state & risk limitation |
| **Traceability** | None | Full machine-readable `reason_chain` with $E0$–$E5$ evidence links |
